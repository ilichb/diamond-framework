# avip_zk_prover — M4a and M4b measurements

Off-chain side of M4 (plan §5.5). Nothing here is a production circuit: M4 proves
the pipeline and its cost, not a deployment (§5.5.6).

## Run

```text
src/zk/scripts/m4a_report.sh                             # every M4a measurement -> scripts/m4a_output.txt
src/zk/scripts/m4b_report.sh                             # the real key + the real proof -> scripts/m4b_output.txt
src/zk/scripts/m4b_fixture.sh                            # emit the Solidity fixture the contracts verify
cargo test                                              # fast tests; the heavy proof is #[ignore]d
cargo test --release -- --ignored                       # the 32,768-bit aggregated range proof
cargo run --release --bin m4a-report -- --write-digest  # refresh fixtures/tensor_digest.txt
cargo run --release --bin m4b-report -- --smoke         # the M4b pipeline in seconds (8 entries), not for the table
src/zk/scripts/check-yoloproofs-gate.sh                 # re-verifies the §5.5.5 crate finding
```

Pins are exact (`=0.6.0`, `=5.0.0`, `=4.1.3`, `=3.0.0`) and `Cargo.lock` is
committed. The **first** `cargo fetch` needs the registry; after that
`cargo build --offline` works. The one command that always needs a fetch is
`check-yoloproofs-gate.sh`, because it builds a throwaway crate against
`bulletproofs`.

| V3 (Poseidon + norm) | **93,608 constraints** (Poseidon share 60,748), satisfied |

| Durations (stderr) | prove 3.2–5.4 s, verify 0.27–0.44 s — load-dependent, see below |

| M4b: V3 in the statement wrapper `[root, epoch, certifiedNorm]` | **94,438 constraints**, 4 instance variables, `ic = 4`, satisfied |
| M4b: the wrapper's cost over V3 | **+830 constraints (+0.9%)**, all of it `epoch < 2^64` |
| M4b: key / proof | 93,193 `a`-queries; proof 128 B compressed, **256 B on-chain** |
| M4b durations (stderr) | setup 6.6 s, prove **3.9 s** (§5.5.4's gate is 120 s), verify 1.3 ms |

The numbers live in `scripts/m4a_output.txt`; that file is what the M4a note
quotes, and it is regenerated by the one command above. Re-running the script
reproduces it **byte for byte**: `render` emits only quantities a re-run pins
(counts, sizes, the digest, `satisfied`), while the wall-clock durations go to
stderr through `render_timings`, because the same revision measured
`3.300 s / 0.272 s` and `5.427 s / 0.442 s` under different load. Verify that
with two runs and `diff`; there is no other way to tell a timing shift from a
real change.

## M4b — the outer layer (plan §5.5.4, delivered in §5.5.9)

`scripts/m4b_report.sh` runs the whole pipeline over the committed fixture:
measure V3 *in the statement wrapper* (one more public input, `epoch`, plus the
`epoch < 2^64` bound that keeps its `ic` entry from being the identity), generate
the development key, prove the fixture statement, verify it, and check that
`epoch`, `root` and `norm` are each bound by re-verifying with each one perturbed.
`scripts/m4b_output.txt` is that table, and it is reproducible byte for byte
because both RNGs are seeded (`SETUP_SEED`, `PROOF_SEED`).

`scripts/m4b_fixture.sh` emits
`integrations/avalanche/test/fixtures/M4bGroth16Fixtures.sol`: the same key, the
same proof and the statement `[root, epoch, certifiedNorm]`, in the shape
`Groth16Verifier` is installed with. `integrations/avalanche/test/M4bRealKey.t.sol`
then asserts that the frozen contracts accept it — `verify` and
`AVIPRegistry.verifyThreshold` — and that perturbing any component flips the
answer, the epoch included (a fresh epoch with the same root is rejected, which is
what an *unused* public input would not be).

**The key is a development key.** One phase-2 contributor, both seeds committed
and written into the fixture, so the toxic waste is public and forgeries are free.
It measures the pipeline and exercises the frozen verifier; it carries no security
claim, and the ceremony that would is §11. The key digest in `m4b_output.txt` is
`keccak256` of ark's canonical serialization; `M4bGroth16Fixtures.KEY_DIGEST` is
the *on-chain* digest — `keccak256(abi.encode(vk))`, 25 ABI words — and the
Solidity test compares it against the contract's own `verifyingKeyDigest()`, so
the two encoders cannot drift apart silently.

## Findings recorded against the plan

1. **§5.5.2, the V2 row**: "Pedersen over BN254 G1 recomputed inside the
   circuit" is *not* native — G1 coordinates are in `Fq` while the Groth16/BN254
   constraint field is `Fr`. `E0277`; probe kept in
   `tests/field_nativity_probe.rs`.
2. **§5.5.1, the relation**: `Σ T_i² = certifiedNorm²` has no witness for real
   tensors (`204 ≠ 14²`). The circuit certifies the floor
   `c² ≤ Σ T_i² < (c+1)²`, which leaves `AVIPRegistry.verifyThreshold`'s
   comparison unchanged because `Θ_r` is an integer.
3. **§5.5.3, the object**: the aggregated API accepts only widths
   `{8, 16, 32, 64}` and power-of-two value counts, so the plan's `500 × 60`
   bits are measured as `512 × 64` (padded), and the paper's `0.72 KB` is an
   under-estimate by 1.70×.
4. `CmpGadget for [T]` in `ark-r1cs-std 0.6.0` does not compare correctly — its
   `∧ᵢ (aᵢ > bᵢ ∨ equal_up_to_i)` rejects `"10" ≥ "09"` — so no inequality in
   `native.rs` uses it; both are decided by a bound plus a difference.
