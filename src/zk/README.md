# avip_zk_prover — M4a, M4b, M4c and the M7c bridge

Off-chain side of M4 (plan §5.5) plus M7c's bridge between the prover's root and
the registry's (§5.10). Nothing here is a production circuit: M4 proves the
pipeline and its cost, not a deployment (§5.5.6).

## Run

```text
src/zk/scripts/m4a_report.sh                             # every M4a measurement -> scripts/m4a_output.txt
src/zk/scripts/m4b_report.sh                             # both variants of §5.5.2 end to end -> scripts/m4b_output.txt
src/zk/scripts/m4b_fixture.sh                            # emit the Solidity fixture the contracts verify
src/zk/scripts/m7c_report.sh                             # M7c: the statement's root tied to the registry's -> scripts/m7c_output.txt
cargo test                                              # fast tests; the heavy proof is #[ignore]d
cargo test --release -- --ignored                       # the 32,768-bit aggregated range proof
cargo run --release --bin m4a-report -- --write-digest  # refresh fixtures/tensor_digest.txt
cargo run --release --bin m4b-report -- --smoke         # the same pipeline in seconds (8 entries), not for the table
src/zk/scripts/check-yoloproofs-gate.sh                 # re-verifies the §5.5.5 crate finding
```

Pins are exact (`=0.6.0`, `=5.0.0`, `=4.1.3`, `=3.0.0`) and `Cargo.lock` is
committed. The **first** `cargo fetch` needs the registry; after that
`cargo build --offline` works. The one command that always needs a fetch is
`check-yoloproofs-gate.sh`, because it builds a throwaway crate against
`bulletproofs`.

## M4b — the outer layer (plan §5.5.4, delivered in §5.5.9)

`scripts/m4b_report.sh` runs the whole pipeline over the committed fixture:
measure V3 *in the statement wrapper* (one more public input, `epoch`, plus the
`epoch < 2^64` bound that keeps its `ic` entry from being the identity), generate
the development key, prove the fixture statement, verify it, and check that
`epoch`, `root` and `norm` are each bound by re-verifying with each one perturbed.
`scripts/m4b_output.txt` is that table, and it is reproducible byte for byte
because both RNGs are seeded (`SETUP_SEED`, `PROOF_SEED`).

`scripts/m4b_fixture.sh` emits
`integrations/avalanche/test/fixtures/M4bGroth16Fixtures.sol`: the same key, the
same proof and the statement `[root, epoch, certifiedNorm]`, in the shape
`Groth16Verifier` is installed with. `integrations/avalanche/test/M4bRealKey.t.sol`
then asserts that the frozen contracts accept it — `verify` and
`AVIPRegistry.verifyThreshold` — and that perturbing any component flips the
answer, the epoch included (a fresh epoch with the same root is rejected, which is
what an *unused* public input would not be).

**The key is a development key.** One phase-2 contributor, both seeds committed
and written into the fixture, so the toxic waste is public and forgeries are free.
It measures the pipeline and exercises the frozen verifier; it carries no security
claim, and the ceremony that would is §11. The key digest in `m4b_output.txt` is
`keccak256` of ark's canonical serialization; `M4bGroth16Fixtures.KEY_DIGEST` is
the *on-chain* digest — `keccak256(abi.encode(vk))`, 25 ABI words — and the
Solidity test compares it against the contract's own `verifyingKeyDigest()`, so
the two encoders cannot drift apart silently.

## Findings recorded against the plan

1. **§5.5.2, the V2 row**: "Pedersen over BN254 G1 recomputed inside the
   circuit" is *not* native — G1 coordinates are in `Fq` while the Groth16/BN254
   constraint field is `Fr`. `E0277`; probe kept in
   `tests/field_nativity_probe.rs`.
2. **§5.5.1, the relation**: `Σ T_i² = certifiedNorm²` has no witness for real
   tensors (`204 ≠ 14²`). The circuit certifies the floor
   `c² ≤ Σ T_i² < (c+1)²`, which leaves `AVIPRegistry.verifyThreshold`'s
   comparison unchanged because `Θ_r` is an integer.
3. **§5.5.3, the object**: the aggregated API accepts only widths
   `{8, 16, 32, 64}` and power-of-two value counts, so the plan's `500 × 60`
   bits are measured as `512 × 64` (padded), and the paper's `0.72 KB` is an
   under-estimate by 1.70×.
4. `CmpGadget for [T]` in `ark-r1cs-std 0.6.0` does not compare correctly — its
   `∧ᵢ (aᵢ > bᵢ ∨ equal_up_to_i)` rejects `"10" ≥ "09"` — so no inequality in
   `native.rs` uses it; both are decided by a bound plus a difference.

## M4c — V2′ against V3, and `D-M4-0` (plan §5.5.2, in §5.5.10)

M4c builds the variant §5.5.2 only names and runs it through **M4b's own wrapper**,
so the decision compares two rows of one table instead of two pipelines.
`scripts/m4b_report.sh` now measures both: the pinned V3 section first (byte
identical to the pre-M4c file), then the `D-M4-0` duel.

**What V2′ is.** Pedersen over Baby Jubjub (`ark-ed-on-bn254`). Its **base field
is `Fr_BN254`**, which is why the coordinates are native in this circuit — and why
V2′ is not V2 (BN254 G1, coordinates in `Fq`). Its **scalar field is a different
prime**, so the scalar mul cannot be fed `FpVar`s: `pedersen_commit` takes the
*bit decompositions* §5.5.3's range check already pays for, and the bases —
public parameters — are constant 2-bit-window tables. `root` is the commitment's
**x-coordinate**, because the frozen statement has one `uint256` for it; a full
point would need a second word, which is a §5.5.7 (M7) question.

**The verdict, and how close it is.** V3 wins by 59,250 constraints (94,438 vs
153,688, +62.7%) and by one curve: a V2′ implementation must carry Baby Jubjub as
well as BN254, while V3's commitment is field arithmetic inside the same circuit.
The gap per entry is the whole story — Poseidon ≈121 constraints per entry
(60,748 for 500), Pedersen 240, i.e. 30 two-bit windows of 8 constraints each. That
is a property of the 0.6.0 gadget, so the verdict reads "comfortable on the
measured gadget, a tie on a hypothetical one": a 4-bit window would roughly halve
the Pedersen share to ≈60,000, within a few hundred constraints of Poseidon's
60,748 — and the second criterion (one curve instead of two) is what would decide
then.

**Why it is a decision and not a preference.** `duel_verdict` computes it from the
two measurements — constraints first, curves to break a tie — because §5.5.4
declares no numeric threshold for this branch; the table prints the criterion next
to the numbers it applies to. Both variants reach the contract identically:
`ic = 4`, the same three public inputs in the same order, the same 256-byte
on-chain proof. Nothing on-chain changes, and `M4bGroth16Fixtures.sol` is
untouched: V3 is what M4b installed, and V3 is what the verdict keeps.

Validated: `cargo test` → *29 passed, 0 failed, 1 ignored* (the ignored one is
M4a's 32,768-bit range proof; 6 of the 29 are V2′'s, in `native.rs`, and 4 are in
`tests/groth16_statement_shape.rs`); `cargo clippy --all-targets -- -D warnings`
and `cargo fmt --check` clean; both scripts re-run → their committed outputs
(`scripts/m4a_output.txt`, `scripts/m4b_output.txt`) byte identical;
`bash verification/audit-gate.sh` → *PASS=11, FAIL=0*.

## M7c — the Pedersen/Poseidon ↔ keccak Merkle bridge (plan §5.4 item 4 (c), §5.10)

M4's statement carries `root = Poseidon(T)`; `AVIPRegistry` verifies inclusion
against `keccak256` leaves. Nothing tied the two readings of the same tensor
together, which is gap **A7**. Option (c) — the one §5.5.7 selects — is a
*recomputable link*, not a proof:

```text
link = keccak256(abi.encodePacked(bytes32 merkleRoot, uint256 statementRoot, uint256 epoch))
```

Three fixed-width words, so the packed encoding is unambiguous — the property
`abi.encodePacked` does *not* have in general and does have for these types.
`src/bridge.rs` builds the tree by folding `avip_datalayer::commitment`'s own
`Epoch` through its `merkle_root`, so `verifyEntry`'s convention cannot drift from
the registry's; it takes the statement root from `native::poseidon_commitment`,
the same function that fills `groth16::circuit_for`'s public input; and it takes
the leaf key `i` from the position of `T[i]` in the 20-byte `validator` slot. No
part of the registry's fold or of the commitment is restated. `Bridge::open`
produces the tensor's claim; `verify(entries, claim)` recomputes everything from
the tensor alone and returns `Bound` or, first failure first,
`Unbound(StatementRoot)` / `Unbound(Link)`.

What it does **not** do, and why that is the point: keccak is not proved inside
the circuit — the proof certifies the norm, the tie is off-chain and recomputable
by any peer; a verifier holding only the two roots learns nothing, because the
link needs the tensor (side-by-side roots would be an `ic.length` change §5.5.7
does not decide); and for V2′ the statement's `uint256` is the commitment's
**x-coordinate**, so a full point would need a second word — §5.5.10's residual is
a measured row of the table, not a footnote. The `T → W` identity stays unclaimed
(§10 D-7).

`scripts/m7c_report.sh` is the one command and `scripts/m7c_output.txt` the pinned
table: byte-stable across runs, and guarded in both directions against
`integrations/avalanche/test/fixtures/M4bGroth16Fixtures.sol` — every statement
value the contract test installs must appear in the fresh table, and the pinned
link must be the link this revision computes. Failure leaves the pinned file
untouched. `cargo test` closes the other direction: every number in the committed
table is recomputed in `tests/m7c_bridge.rs`, so library and artefact cannot drift
apart silently.

Validated: `cargo test` → *42 passed, 0 failed, 1 ignored* (9 of them `bridge.rs`'s
own and 4 in `tests/m7c_bridge.rs`); `cargo clippy --all-targets -- -D warnings`
and `cargo fmt --check` clean; `scripts/m7c_report.sh` twice → `m7c_output.txt`
byte identical, and its `11/11` internal checks hold.

## Remaining for M4

The paper-literal recursive construction (§5.5.7) and the ceremony (§11). V2′ is
measured, and `D-M4-0` is closed as **V3**. M4b did not need V2′ — V3 is the
circuit whose key it derived — and the pipeline stayed circuit-agnostic, so the
variant switch (`groth16::Variant`, `variant_circuit_for`) is what M4c added around
it rather than a second pipeline. The *Pedersen ↔ Merkle bridge* that M4 left open
is delivered by M7c (§5.10), in this crate because it needs the prover's own
commitments.
